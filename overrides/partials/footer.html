{# overrides/partials/footer.html Site-wide override of Zensical's own partials/footer.html — applies to EVERY page, not just the landing page. Resolved automatically via theme.custom_dir (mkdocs.yml); no per-page template selection needed, since base.html includes "partials/footer.html" directly on every page. Structure, top to bottom: 1. Footer prev/next navigation — UNCHANGED, copied verbatim from Zensical's own footer.html (github.com/squidfunk/mkdocs-Zensical, Zensical/templates/partials/footer.html). Still respects theme.features -> navigation.footer and per-page `hide: - footer` front matter exactly as before. 2. Documentation Directory — NEW. A six-column sitemap grid, reusing .footer-grid (extra.css) — the same CSS Grid `auto-fit, minmax()` pattern used by every other multi-column section on the landing page. This is the Zensical equivalent of a Bootstrap `.row` of `.col-*`: Zensical ships no such utility system, so every multi-column layout in this project is hand-rolled CSS Grid under a semantic class name rather than a framework utility class. `.md-grid` here is Zensical's OWN width-constraining container class (used identically for the nav above and the copyright bar below) — the closest equivalent Zensical has to Bootstrap's `.container`. It is NOT a column system; `.footer-grid` supplies the columns. Wrapped in `.md-typeset`, same as Zensical's own copyright block just below it, for the same reason the hero partial is: outside `.md-content`, nothing else supplies that class, and every rule in typography.css/components.css depends on it. Every href below uses MkDocs' own `url` filter against the FINAL clean-URL path (e.g. "introduction/overview/", NOT the .md source path) — confirmed against MkDocs' own url_filter implementation, which normalizes a given URL relative to page/base_url context. A hand-typed relative path (as the old markdown-only version used) only worked because it lived exclusively on the root-level homepage; here it must resolve correctly from every page at every nesting depth, so it goes through the filter instead. 3. Footer meta (copyright / social) — UNCHANGED, copied verbatim. hooks/copyright.py's {year} resolution and mkdocs.yml's extra.social list continue to work exactly as before; nothing about them was touched. IMPORTANT: keep sections 1 and 3 byte-for-byte in sync with upstream if mkdocs-Zensical is ever upgraded and its footer.html changes — check that file's diff first. Only section 2 is this project's own content. #}
